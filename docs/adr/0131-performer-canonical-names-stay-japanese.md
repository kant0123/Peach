# ADR-0131：女优规范名使用日文名

- 状态：已采纳
- 日期：2026-10-30
- 修订：ADR-0122 的中文规范名导入；`docs/SOURCING.md` 的规范名选择

## 背景

此前规范名优先用简体中文通行名：种子导入把规范名换成中文，译名脚本把日文名映射成中文、把日本字形逐字换成简体。结果是 `純白彩永` 变成 `纯白彩永`，`逢沢みゆ` 变成 `逢泽美优`。女优在作品来源、官网和社媒上都以日文名出现，中文写法只是转写，规范名与来源对不上，名字链、署名与搜索都要多绕一步。

## 决策

女优规范名使用日文名，字形保持来源写法。中文译名与简体写法降为别名，搜索照样命中；界面的中文显示由 `performer_name_display` 按字形投影，不改规范名。

种子导入不再改规范名。种子包里的中文规范名只用于匹配，中文写法作为别名补入。`seed_pack.planned_names` 与 `revert_names` 保留，用于撤回旧版种子已经写下的中文规范名。

`localize_performer_names.py` 不再写 ledger，只产出审计 CSV。已经换成中文的规范名由 `restore_japanese_performer_names.py` 恢复：只采用账本里已留存的日文写法，按映射记录、自动改名前的原名、字形归一前的原名取证，候选必须已是该女优的别名。取不到证据记「未取得」，用户选定的名字与被其他女优占用的目标名不动。改名走 `prefer_entity_name`，同步作品署名与兼容标签，原中文名保留为别名。默认只预演；真实写入须 `--apply --backup`，由用户授权后执行。

## 后果

- 已发布种子包里的中文规范名不必重导：导入不再读它们作规范名。下次导出基于已恢复的账本，规范名自然是日文。
- 已安装的账本在运行恢复脚本前保持现状。恢复前的名字留作别名，可随时用 `prefer_entity_name` 换回。
- `harvest_javdb_cn_names.py` 取回的中文写法只经 `apply_alias_candidates.py` 落为别名。

## 验证

临时账本覆盖种子导入不改名、旧种子改名可撤回、各证据来源、人工选择保护、重名冲突、预演不写库、写入要求备份、别名保留与署名同步及重复执行不变。无需新增依赖或修改数据库结构。
